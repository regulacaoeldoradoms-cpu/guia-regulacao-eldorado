# Local synthetic theme audit

Run from `testing/browser`: `npx playwright test --config playwright-dark-audit.config.mjs` (requires the pinned local Playwright package; Windows uses installed Google Chrome, Linux uses Playwright's bundled Chromium with explicit `channel: 'chromium'`). Both use the full browser's new headless implementation; leaving the Linux channel unspecified would select the separate `chromium-headless-shell`. Install dependencies with `npm install --no-package-lock --no-audit --no-fund`; on Linux, also run `npx playwright install --with-deps chromium`.
For the initial inventory, set `DARK_AUDIT_REPORT_ONLY=1`; this intentionally records defects without asserting zero. `DARK_AUDIT_ROUTES=/agenda/,/telemedicina/` limits routes. Never use report-only results as acceptance. `--grep "computed surfaces"` runs only the route inventory while state-specific specs are under development. `DARK_AUDIT_REUSE_LOCAL=1` permits reuse of a manually started `node serve-dark-audit.mjs` on the same fixed loopback origin; it does not enable a remote target.

The new server binds only 127.0.0.1:4176, accepts GET/HEAD and serves an explicit public-file allowlist. The new config has no remote-base option. Browser requests outside this exact local origin are intercepted and fulfilled by synthetic fixtures or fail closed with 503. Service workers, WebSockets, EventSource, beacons, DNS to nonlocal hosts, browser background networking and pings are disabled. Neither Worker, Drive, telemetry nor production is contacted. Fixture usernames, patient details and email are synthetic. Product HTML, CSS and JS are served unchanged. Protocol descriptions are replaced with deterministic synthetic text before the product parses the technical source; IDs, specialty names and classification keys remain for functional routing. The evidence collector also replaces residual hardcoded narrative text inside the medical/reception/protocol detail and print containers, keeping the real DOM structure and controls. No repository data file is modified. Original fixture PDF can be reused from `testing/central-docs/fixture.js` for expanded viewer/editor scenarios.

Every route runs desktop and mobile and records screenshots plus computed styles for dark screen, light screen and print. Routes are discovered from public HTML with explicit source/testing/data exclusions in `dark-audit-routes.mjs`, including three documented redirect aliases. An unexpected destination fails coverage. The collector inspects actual rendered DOM and `::before`/`::after`, alpha-composited backgrounds and gradient stops with relative luminance >=0.45 and area >=96px². Gradient layers are composited back-to-front, including element opacity; gradient endpoints provide an approximation rather than pixel-level analysis. The narrow exception list in `dark-audit-surfaces.mjs` documents intentional PDF paper, color data, the light-theme preview, a small masked status glyph, and the documented gold Altas button/card zones. That gold exception names specific selectors and zones; there is no general exemption for cards, modals or tables or all their descendants. Findings include the selector, color, opacity, mask, inline style and matching background declarations with their stylesheet, media/support conditions and `!important`; these are source candidates, not a claimed definitive cascade winner. Low text contrast is reported separately for manual review because ancestor images/gradients require visual verification.

`network-coverage.json` lists every intercepted request, unknown fixture endpoint and JavaScript error. An unknown API is a coverage gap and fails strict acceptance. No authentication or backend functionality is validated by mock success. Initial route scans cover rendered startup states; expanded modal/dialog/dropdown/editor states require UI interactions and explicit state assertions. No image pixels, PDF contents, browser-native select popup or shadow DOM are interpreted by the CSS detector. `node summarize-dark-audit.mjs` produces `results.summary.json` from the Playwright JSON report.

For actual base-commit regression comparison, set `DARK_AUDIT_COMPARE_BASE=1`, optionally `DARK_AUDIT_BASE=origin/main` (default), and run `--grep "preserve (light|dark)"`. These tests compare all 24 non-alias routes on desktop/mobile for light screen and dark print: 96 checks. Changed tracked CSS, JS and HTML are fulfilled from `git show` at the resolved base SHA in a second load of the same synthetic route. Computed styles and layout must be identical, and any new JavaScript error fails. PNG pixels allow only an absolute rasterization tolerance of two differing pixels with a maximum channel delta of one; reports retain exact SHA256 values and whether the files are identical. This bound is not a percentage and never relaxes computed/layout checks. Each report lists errors observed in current and base, making a pre-existing error distinguishable from a new regression without suppressing it. The comparison helper accepts a `prepare(page)` callback to replay identical interactive states. `git show` requires the base commit to exist locally (CI fetches full history). This never updates a golden screenshot. Keep generated `test-results-dark-audit/` out of commits.

Git comparisons run with an explicit repository-root working directory. Reports include the changed product paths and SHA256 of the actual current/base sources served to the browser; the changed global theme stylesheet must be served in both phases. Both phases use intercepted, frozen source maps to avoid different resource delivery behavior. The helper resets screen media before each navigation, prepares real controls, then switches to the requested screen/print media and waits for fonts. Selectors retain full ancestry to a unique ID. Snapshots include active pseudo-elements, background images, exact viewport rectangles, border radii, transforms and backdrop filters, alongside the existing selected styles and rounded dimensions. Pseudo-element rectangles are explicitly labeled as their owning element's rectangle; their own computed dimensions remain recorded. Use the spec filename `portal-dark-preservation.spec.mjs` to select precisely the 96 startup comparisons; the broader grep also includes state-specific preservation tests.

Each source phase must independently produce a stable computed/layout snapshot. Exact repeated PNG bytes are required when Chromium's rasterizer is stable; when Linux Chromium alternates raster-only text/edge pixels while the computed/layout snapshot is identical, raster repeatability is recorded as diagnostic instead of failing the source phase. The final 2-pixel/1-channel current-vs-base gate remains mandatory whenever both source phases are raster-stable. Two narrowly bounded diagnostic classes are accepted only with exact DOM/computed/layout equality and zero new JavaScript errors: (a) low-amplitude raster <=0.025% of pixels with max channel delta 12; or (b) extremely sparse glyph-edge raster <=64 pixels, <=0.005% of the image, with max channel delta 32. Any structural/style/layout difference still fails. A second, explicitly bounded raster-only class is accepted only when computed/layout snapshots are exactly equal: at most 0.025% of screenshot pixels may differ, with maximum channel delta 12. This exists for deterministic Linux text-edge raster differences on very large pages; any DOM/style/layout difference or larger-amplitude pixel change still fails. Current and baseline are loaded in separate fresh pages inside the same synthetic context, with a fixed audit clock, scroll positions reset, focus/hover cleared and CSS motion disabled only for the capture phase. This removes browser history/compositor state without changing product files or the final pixel threshold. The helper does not select a frame by comparing it with the opposite source. The pointer is moved outside the viewport before navigation and after preparation. Styles are collected after full-page capture settles native text metrics. Reports preserve each capture hash and the actual theme/media; a mode mismatch fails. Council/Citizen light and dark-print cases use separate contexts with matching account/storage fixtures, preventing account hydration from replacing the requested theme. The complete matrix is 210 tests and 120 actual base comparisons.

Medical preservation cases have a 180-second execution budget: the full mobile catalogue exceeds 90 million physical pixels, and repeated software captures exceeded the former 45/90-second budgets despite identical final images/styles. The catalogue and screenshots are not truncated; the five-capture bound and all acceptance assertions remain unchanged.

The browser uses `--disable-gpu --disable-skia-runtime-opts` for controlled software rasterization. Repeated Windows loads of the same source exhibited different backdrop-blur pixels with identical full computed styles and geometry; the software/Skia configuration was evaluated against repeated current/base captures without hiding filters, changing CSS or increasing tolerance. Linux headless-shell still produced raster differences and one unstable baseline in run 36031472446 (196/210, diagnostic only). The explicit full-browser channel aligns the headless implementation with local Chrome, as documented by [Playwright](https://playwright.dev/docs/browsers#chromium-new-headless-mode); acceptance still requires the complete strict matrix. Failed stability now attaches the last two PNGs and snapshots, retaining the five-attempt bound. This is a controlled Chromium capture environment, not a claim of identical pixels across physical GPUs.

## Isolated CI

`.github/workflows/portal-dark-audit.yml` runs on relevant pull requests and manual dispatch. It checks out full history and requires `origin/main` to resolve, installs Node.js 22 and bundled Chromium on Ubuntu, then executes every `portal-dark-*.spec.mjs` for both configured device profiles. `DARK_AUDIT_COMPARE_BASE=1` includes the 96 light/print comparisons; report-only mode and existing-server reuse are explicitly disabled. Playwright starts the read-only loopback server itself. The workflow has only repository read permission and no secrets, deployment, production checks or authenticated external services.

All evidence uses `testing/browser/test-results-dark-audit/` by default; set `DARK_AUDIT_OUTPUT_DIR` to another directory when running an independent local subset to avoid overwriting another run. The JSON reporter writes `results.json` inside that same directory. Tracing is off by default; `DARK_AUDIT_TRACE=1` retains traces on failures when specifically debugging. CI attempts to generate `results.summary.json` and upload the entire directory even after a test failure, retaining artifacts for seven days. Summary, full reports and PNGs are uploaded separately so the original 596 MB archive does not exceed the artifact connector's 512 MB limit. No evidence is discarded; the summary does not replace the full reports.

The dependency installation downloads public npm packages and Chromium; application requests during tests use only loopback files or modeled synthetic responses. There is no browser egress test against production. Since this package has no committed lockfile, CI uses `npm install --no-package-lock`, not `npm ci`; the direct Playwright dependency is pinned, while transitive resolution can change. Comparison images are generated for current and baseline code in the same browser run, so no Windows screenshot is used as a Linux golden image. This covers Chromium desktop and emulated Pixel 7, not physical mobile devices, WebKit, Firefox or platform-native popup rendering. Mocked API success does not prove backend behavior, Drive access or production deployment. A prepared workflow is not evidence of a successful GitHub Actions run; record its actual result separately after publication.
